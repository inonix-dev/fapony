# fapony — Edge Cases, Handled

> **Used by:** [CLAUDE.md](../CLAUDE.md) — moved out because this is a *lookup*, not a *rule*.
> `grep` here when you hit strange behavior that feels familiar. Do not load every session.

| Edge Case | Handling |
|-----------|-----------|
| Dangerous shell commands (memory claim/close/add, evidence collector cmds, `install`'s `claude mcp add`) | `assertSafe()` deny-list ([src/safety.ts](../src/safety.ts)) runs before every config-sourced shell spawn — it's code, not prose |
| fapony writing into a worktree | Allowed only on the owner's order, under three checkable limits (rule 6): **6a** runtime state never lives in a worktree — the ledger DB is `~/.config/fapony/` only, and its path must never come from an arg/config pointing at a worktree · **6b** a command that reads code writes only to a user-named path (`--out`, a filename in argv) · **6c** overwriting an existing file asks first or refuses |
| `fapony update` run from src/ | ROOT = `join(import.meta.dir, "..")` — miss it as bare `import.meta.dir` and git pathspecs (`-- bun.lock`) go relative to src/ → lockfile changes go undetected and the version reads "unknown" (tripwire test in update.test.ts) |
| ~/.config/fapony/ missing | mkdirSync(recursive) before opening the db |
| repeated `fapony init` | Check every dir (plan/spec/memory/evidence.json) → error on anything pre-existing, never overwrite |
| memory: null plus an existing `.fapony/.memory/` | Default wiring uses claim/close/add automatically, via `fapony mem` |
| Evidence cmd the agent proposes itself, outside the allowlist | Never run — reported as *proposed — not executed* ([src/mcp/evidence.ts](../src/mcp/evidence.ts)) |
| AI reusing a plan filename over an old one | `skill/plan-with-pony/SKILL.md`, "Resolve where plans live first" — `ls <planDir>/` (plus `paths.doneDir`) for collisions before writing, always |
| `usage-web` slow on first load when the OpenCode/ZCode part table is huge (100k+ rows) | Fixed — `usage-web` reads the cache (`~/.config/fapony/usage-cache.jsonl`), never the session log · scanning happens only when a human runs `fapony usage-scan` · `--full` moved to a `usage-scan` flag |
| `usage-web` with no cache | Print "run `fapony usage-scan` first" — never scan on its own (done criteria #5) |
| gate events without `session_id` → `by model` reads `—` down the column (15/17 on the real machine) | Don't ask for a new field — **infer at read time**: every client already logs the session's directory + time span; [activeSession.ts](../src/session/activeSession.ts) finds the span *covering* the gate's ts (not the latest span), narrowest wins on overlap · always tag `modelSource: "inferred"`, never present it as caller-declared · works retroactively on old rows with nothing rewritten (2 declared → 18 attributed) |
| Does every other user need to paste rule 7 into their own CLAUDE.md? | **No** — MCP `initialize` answers `instructions` ([transport.ts](../src/mcp/transport.ts) `SERVER_INSTRUCTIONS`), the client injects them into context itself = all clients covered without touching anyone's rule files · rule 7 in this repo's CLAUDE.md is just emphasis for this repo, not the mechanism · that text is paid every session by everyone — **keep it short, never stuff more in** |
| cost/efficiency in `stats`/`report`/telemetry always empty | **Deleted** — the whole declared-cost chain (spawn event + `pricing` + ES/CPQ + avgValue) derived from `beginSpawn`/`endSpawn`, which left with the execute→review loop (see History). No writers remain, so the numbers were `—` forever · one cost line survives: the client's own passive session log (`fapony usage-scan`/`usage-web` — MCP tool removed 2026-09-20) — OpenCode logs real cost, ZCode/Claude Code/Codex log 0 |
| Claude Code tokens suspiciously low (`4.2k in / 1.1M out`) | **Cache is nearly all of input** — bare `input_tokens` is not real input; every reader must add cache read + cache write (`sumInput()` in [findModel.ts](../src/session/findModel.ts) is the one every client uses) · signal that accounting is broken: a coding agent with input < output is impossible · note: the catch-all around the session reader's query swallows schema mismatches into silent `null` — add a SQL column and old fixtures just lose the value without erroring |
| per-model tokens inflated out of proportion | Tokens are **per session** but gates are per round — 58 gates came from 35 sessions (one session can own up to 5 gates); adding straight up multiplies unevenly per model = wrong ranking · `GateWindow.sessionId` exists to dedupe, `addSessionTokens()` in [stats/data.ts](../src/stats/data.ts) charges once per session per bucket |
| test comparing output twice, flaky red | Not a floating flake — the passive reader reads session logs **the agent is writing while the test runs**; numbers move between the two renders · pin `FAPONY_OPENCODE_DB` / `FAPONY_ZCODE_DB` / `FAPONY_CLAUDE_PROJECTS_DIR` / `FAPONY_CODEX_SESSIONS_DIR` at nonexistent paths so usage is empty on both sides |
| new PR says *"This branch has conflicts"* with nobody colliding | Last round `dev` was **squash-merged** — squash writes new commits, so dev's commits never become ancestors of `main`, and git reads "both sides touched the same lines" for identical work · **this repo always uses `gh pr merge --merge`, never `--squash`/`--rebase`** — both rewrite history = the same divergence · two-layer reason: (1) commits here are already one-concern each per rule 3, so squash discards that work every merge — `git blame` then answers every line with the whole branch's message (2) squash inserts a forgettable step into the critical path, while `--merge` has nothing to forget because dev is already an ancestor of main — only `git merge --ff-only origin/main` remains (no force) · if already squashed, `git reset --hard origin/main` on dev right after the merge is mandatory, not optional ([skill/git-ship](../skill/git-ship/SKILL.md)) · verify it's really clean: `git merge-base --is-ancestor origin/dev origin/main` exits 0 · prove a phantom conflict before fixing: `git diff <merge commit on main> <PR cut point>` empty = main holds nothing to take, then close with `git merge -s ours origin/main` (confirm tree hash equal before/after) · `main` is therefore a graph that forks every PR, by design — read at PR level with `git log --oneline --first-parent main` |
| `.fapony/.memory/` placed by `fapony init`, but the log lands elsewhere | store.ts used to find the dir from **git root + a monorepo guess**, never looking at where it sits — single repo: code in `.fapony/.memory/`, log in `<root>/.memory/` · the real breakage: `apps/<x>/.fapony/.memory/` in a monorepo → writes into **another app's** log (root=wt-vela, app=vela) · fixed with `import.meta.dir.includes("/.fapony/.memory")` = a scaffolded copy, anchored at its own folder · the shared copy (one codebase at root, per-app logs) defaults to `<app>/.fapony/.memory`, falling back to legacy `.memory/` only when `log.jsonl` actually exists there (check the file, not the dir) · app is guessed from the first real `{apps,packages,services}/<app>`, but the `unknown app` guard still only knows `apps/` · the discriminator between "shared copy" and "scaffolded copy" at root is **whether the app is guessable**, not "whether an app folder exists" — `fapony init <monorepo root>` lands exactly on the shared-copy path, so judging by `apps/` alone dies at the guard on the first command with the plan sitting next door |
| `git mv` a log into `.fapony/` and tracking silently drops | `.gitignore` ignoring the whole `.fapony/` tree (`**/.fapony/*` + per-dir negations) — moving a file in before adding the negation = silently untracked · the negation must be `!**/.fapony/.memory/` (**dir first** — git cannot re-include files inside an excluded folder) and must start with `**/` (a pattern with a middle slash anchors at the repo root and won't match `apps/<x>/.fapony`) · order: add negation → commit → then `git mv` → check `git ls-files` immediately |
| `verification_report` for one app running another app's tests / a team with no allowlist | The allowlist was one file per worktree (`join(worktree, evidenceFile)`) while a monorepo holds several apps with different test commands · fixed with `resolveEvidencePath(worktree, files[])` in [evidence.ts](../src/mcp/evidence.ts): every file under the same `<group>/<app>/` + an `<app>/.fapony/evidence.json` present → use that file, else the root one (no new `app` field — infer from facts already at hand) · evidence.json **must be committed** (the allowlist is the security boundary the whole team must share) — keep it out of ignore via negation `!**/.fapony/evidence.json` ([test/mcp/evidence.test.ts](../test/mcp/evidence.test.ts) pins app/mixed/empty/missing/custom) |
| `mem plan-sweep` / `plan-check` never working for `fapony init` users | `src/mem/commands/plan.ts` hardcoded `apps/<app>/plan` in **10 places** while `store.ts` already had the single-repo fallback → prints "no plan/" every time, silently · centralized in `store.ts` alone (exports `planDir`/`doneDir`) |
| monorepo with several apps but one `paths.planDir` value | Declaring `planDir` for one app = **every other app points at that app's plans** (vela declares `apps/vela/plan` → `MEM_APP=canalis plan-check` reads vela's) · fixed by **adding no field** and teaching the default instead: `existsSync(<planBase>/.fapony)` → use `.fapony/{plan,done}`, else legacy `plan/` + `plan/done/` — each app migrates into `.fapony/` on its own without touching config, and a declared config still wins as before (covered by test/memory.test.ts) |
| `.memory` copies in other projects going stale when the template fixes a bug | `fapony init-mem` deletes the old `.memory/` + warns about call sites still referencing it · data files (log.jsonl) untouched |
| template guessing paths the `fapony.config.json` already declares | **Config always beats guessing** — `store.ts` reads `paths.planDir`/`doneDir` (vela declares `apps/vela/plan` outright); the `planBase` heuristic survives only as the no-config default · read config **at project level only**: a scaffolded copy in `apps/<x>/.fapony/` must not pick up the monorepo root's config (those are another project's paths) · undeclared `doneDir` → `<base>/done`, unless a legacy `plan/done/` actually exists (vela still uses the old one today, never forced to move) |
| Thai or English prose? | **Split by reader, not by writer** — (1) machine surface (frontmatter keys/values, checkbox syntax, enums) = EN always, tools parse it · (2) anything shipped out (README, SKILL.md, templates, examples, `SERVER_INSTRUCTIONS`, **every string `templates/mem` prints**, **repo docs under `docs/`**) = EN — `fapony init` hands it to the whole world (owner decision 2026-09-22) · (3) prose in plan/spec + **code comments** = the fixing dev's language (Thai here), read only by people who edit this repo |
| shipped PLAN invisible to `plan-sweep` | Detection used to check `^> ✅` on the **first non-empty line** — the current format opens with frontmatter, so the `# title` header is never first anymore · `hasShippedHeader()` checks the first 2KB with a `/m` regex instead |
| test db clobbering the production db (`os.homedir()` cached in Bun ignores `process.env.HOME` changed after process start) | Tests isolating the db must set `process.env.FAPONY_STATE_DIR`, not `process.env.HOME` |
| `Bun.spawnSync` not seeing runtime-set env | Bun snapshots the environment at process start — `process.env.X = "..."` set later **never reaches the child**; pass `{ env: process.env }` explicitly (found testing identity with `GIT_CONFIG_GLOBAL` set while `git config` still answered the machine's real values) · same shape as the `os.homedir()` row above |
| `mem rotate` then `mem find` / `mem_find` forgetting the old rows | The reader used to exclude `log.YYYY-MM-DD.jsonl` outright = the day the 3,000-row threshold hits, closed history vanishes silently — the very rows recall wants most · fixed: `readMemLog` + `allRows()` read the archives too · **but the store's `rows()` must not read them**, or rotate counts rows it just moved out and sucks them back into log.jsonl next round |
| two machines / two people writing one log file indistinguishably | `agent` used to be `$USER \|\| "unknown"` and the filename `git user.name \|\| $USER \|\| "unknown"` — the generic names OSes hand out at install (`admin`/`user`/`owner`/`root`/`ubuntu`) collide on both · generic names now count as **nameless**, falling through to `git user.email` → machine tag (`m-<8 hex>` from machine-id/MAC hash — hashed because this file is committed to git) · pull conflicts between people are absorbed by `*.jsonl merge=union` in the `.gitattributes` that `fapony init` adds |
| `fapony debt` at a monorepo root answering "no conventions.json" while `apps/<x>/.fapony/conventions.json` exists | `worktreeOf()` fired `git rev-parse --show-toplevel` and measured there always — **dropping both cwd and the path passed as argument** · root holds no conventions.json and ≥2 apps have one → the mem resolver (the same one `resolveConventionsPath` uses) answers ambiguous → silence · fixed by walking up from the given path (or cwd) to the nearest dir holding `.fapony/conventions.json`, bounded by the git root, then falling back to the git root (a single repo run from a subdir still scans the whole repo as before) — `fapony debt apps/<x>` works; the root stays silent by design because the app is unanswerable ([src/debt/cli.ts](../src/debt/cli.ts) `worktreeOf`) |
